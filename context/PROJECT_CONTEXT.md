# RiskAtlas: project context

_Last updated: 2026-10-05_

## What it is
Track A entry (Multimodal AI Hackathon 2026): interactive 3D coronary risk map plus explainable dashboard. Predicts
overall CAD and LAD/LCX/RCA stenosis from 52 clinical features (Z-Alizadeh Sani, 303 patients), draws probabilities on a
3D heart, explains them with SHAP, shows physiology against reference ranges and counterfactual what-ifs.

## State of the repo
- `main` at the merge of PR #1 (`229f82c`, 2026-10-05): ML pipeline, FastAPI (`api/`), React + TS dashboard (`web/`),
  three.js `HeartViewer`, docs and submission pack. Not deployed yet.
- Stack: Vite 8, React 19, TypeScript, three 0.186, plain CSS tokens (`web/src/shared/theme.css`). FastAPI backend.
- Tests at merge: 189 Python, 193 web unit/component, 38 browser (Playwright) against the real backend, axe scan clean.
- ML (headline, repeated nested CV): CAD AUC 0.92, LAD 0.84, LCX 0.72, RCA 0.73.
- Not built yet: heartbeat, 17-segment bullseye, report reader (`cv/`), natural-language layer (`slm/`).

- 2026-10-07: performance, after friends said it felt heavy. Measured with Chrome's CPU slowed down (`web/tests/e2e/perf.mjs`, `CPU_SLOWDOWN=4`, `DPR=2`). Found: (1) on a hi-dpi screen the heart drew at up to 2x pixel ratio with 4x MSAA and bloom: 20 fps with 150 ms hitches; (2) React re-rendered the whole stage about 30 times a second to move the chip labels: 28 fps at a 4x slower CPU; (3) the viewer only gave up effects below 20 fps. Fixes: pixel ratio cap 1.5 and 2x MSAA; an adaptive controller (`adaptStep` in `src/atlas/logic.ts`, tested): below about 45 fps it lowers the resolution first (floor 0.55), then drops particles, bloom and auto-rotate, and creeps back up after a calm stretch; chip labels, leader lines and the tooltip are now written to the DOM from refs (`layout()` in `Stage.tsx`), not through React state. Result: 4x slower CPU 28 to 60 fps, 8x slower 11 to 47 fps, hi-dpi 20 to about 50 fps. Also: a full prediction now starts the fast model at the same moment (`commitWithPreview`), so colours and probabilities appear in a second or two even on the slow Render instance while the 35 s full answer is computed; the landing page prefetches the workspace chunk and heart model after 2.5 s.
